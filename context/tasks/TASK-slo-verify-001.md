# TASK-slo-verify-001 — measure the declared Shadow SLOs

**Goal:** replace the SLO table with measurements, so that G1 is entered against numbers rather than
against intentions.

**Domains:** `platform`, `runtime_architecture`

**Stable work item:** `SLO-VERIFY-001`

**Stage:** M4B
**Risk:** LOW technically, MEDIUM in consequence — an unmeasured SLO is discovered by a customer.

## Why this exists

`specs/SECURITY_RELIABILITY_SPEC_V1.md` §20 declares Shadow-stage targets:

| SLO | Shadow target |
|---|---:|
| Deterministic quote p95 | <500ms |
| Agent draft p95 | <15s |
| Agent run hard timeout | 20s |
| Ready-queue dispatch latency p95 | <15s |
| Internal control-plane availability | 99.5% business hours |

`specs/ENGINEERING_SPEC_V1.md` adds `NFR-PERF-002` (staff mutation p95 <1s) and `NFR-PERF-004`
(a 10,000-order list still loads p95 <2s with pagination and indexes).

No work item measures any of them. `RUNTIME-PARITY-001` covers agent latency and cost only, and it
sits behind `AGENT-002`. `MONITORING-001` builds alerting, which tells you when a target is missed
but never establishes that it was ever met. `NFR-PERF-004` in particular is a claim about index and
pagination behaviour at a scale the database has never held.

## Required design

- A reproducible measurement harness, run against the deployed staging or production topology, not
  against a developer laptop.
- Seed to the declared scale for `NFR-PERF-004`: at least 10,000 orders with realistic distribution,
  generated by the same synthetic machinery used elsewhere and containing no personal data.
- Report p50/p95/p99 with the sample size and the measurement window; a p95 quoted from twelve
  requests is not a measurement.
- Exclude what §20's definitions exclude — queue-before-claim time, human time and provider delivery
  time are reported separately from agent processing latency.
- Bind each measured SLO to the corresponding `MONITORING-001` alert, so a later breach pages
  someone.

## Constraints

- Measure; do not tune. If a target is missed, record the miss and open the optimisation as its own
  item rather than changing the target.
- No real customer data in any load fixture.
- Load generation runs against staging. Running load against a production host requires separate
  authorization.
- This item authorizes no capability and makes no provider call; agent-path latency is measured with
  the deterministic transport unless `PROVIDER-TRANSPORT-001` has already landed.

## Required tests

- the harness reproduces its own numbers across two runs within a stated tolerance;
- the 10,000-order seed is present and the list endpoint is measured against it;
- a deliberately slowed dependency moves the measured p95, proving the harness measures what it
  claims;
- every measured SLO has a corresponding alert rule.

## Done when

- every §20 Shadow target and both applicable `NFR-PERF` targets have a measured value with sample
  size and window;
- misses, if any, are recorded as findings rather than silently absorbed;
- the full gate battery passes with no required skips;
- rollback is deleting the harness and its seed data, which removes no evidence and no production
  configuration.
